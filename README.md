# v4-parity

Conformance vectors for Uniswap v4 swap math, generated by executing the real `v4-core` code, plus
harnesses that replay them against off-chain re-implementations (SDKs, aggregator pool simulators).

Aggregators, routers, solvers and wallets quote v4 pools off-chain. If their math differs from
`PoolManager` by even 1 wei they quote wrong, revert, or leak value. Since Uniswap governance
proposal 100 (executed 27 Jul 2026) turned on v4 protocol fees, which v4 charges **on top of** the
LP fee (unlike v3, where the protocol takes a cut of the LP fee), every simulator that was ported
from v3 math has a new way to be wrong.

## What is here

| Path | What |
|---|---|
| `src/Oracle.sol` | Thin wrapper over `v4-core` `Pool`, `TickMath`, `SqrtPriceMath`, `SwapMath`, `ProtocolFeeLibrary`. No math of its own. |
| `gen/generate.mjs` | Seeded generator: random + adversarial pools (tick spacing 1..32767, fees 0..100%, protocol fees 0..1000 pips per direction, 1–6 positions, prices on tick boundaries, 1-wei limits, dynamic-fee overrides) executed on a local anvil node. |
| `vectors/` | Seed 1: 3,000 swap vectors (80% with protocol fee on) + 2,400 math-function vectors. |
| `vectors-nopf/` | Seed 2: 3,000 swap vectors with protocol fees off, to isolate core math. |
| `harnesses/` | Replay harnesses for `@uniswap/v4-sdk` (TS), `uniswap-v4-sdk` (Rust), ParaSwap, KyberSwap and Tycho, each pinned, with reports and minimal repros. |
| `FINDINGS.md` | What the harnesses found. With the right fee, swap amounts match everywhere. Four of 5 engines mishandle protocol fees (2 bugs, 2 missing features); Tycho is correct. |
| `patches/` | Tested fixes for ParaSwap and KyberSwap. |
| `test/ManagerParity.t.sol` | Generated Foundry test replaying every vector through the real `PoolManager` + routers. |

## Guarantees

- **The vectors are the real thing.** Of seed 1's 3,000 swaps, `forge test` replays all 2,656 that succeed without a hook override through
  `PoolManager.unlock → swap` with real ERC20 settlement: 2,656/2,656 match amount0, amount1, price,
  tick and liquidity exactly.
- **Reproducible.** Same seed + same v4-core commit gives byte-identical files
  (seed 1: `swaps.json` sha256 `2651952b…`, `units.json` `3ce1f5bd…`).
- Pinned to v4-core `46c6834698c48bc4a463a86d8420f4eb1d7f3b75`.

## Reproduce

```sh
git clone https://github.com/Uniswap/v4-core lib/v4-core   # then: git -C lib/v4-core checkout 46c68346 && git -C lib/v4-core submodule update --init lib/forge-std lib/solmate
forge build
npm ci
node gen/generate.mjs --seed 1 --swaps 3000 --units 2400 --out vectors
node gen/generate.mjs --seed 2 --swaps 3000 --units 0 --protocolfee off --out vectors-nopf
node gen/codegen-manager-test.mjs vectors/swaps.json 100000 && forge test
```

## Live exposure scan

`node scripts/exposure.mjs [chain ...]` (Node 18+, no dependencies) reads every `ProtocolFeeUpdated`
event on the six PoolManagers since Proposal 100, then reports which pools are fee-on now, the fee values
per direction, and how many of the last 24h of v4 swaps hit those pools. Output: `exposure/<chain>.json`
and `exposure/SUMMARY.md`. Free public RPCs are the default; set `RPC_<CHAIN>` to use your own.
Latest results: [EXPOSURE.md](EXPOSURE.md).

## Vector format

See `harnesses/BRIEF.md`. Key conventions: `amountSpecified < 0` is exact input (v4, opposite of v3);
amounts are `BalanceDelta` from the swapper's side (negative = paid in); `swapFee` is the total fee in
pips actually applied after the protocol fee is added.
