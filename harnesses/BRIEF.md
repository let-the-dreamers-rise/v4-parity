# v4-parity: harness brief for one target implementation

We are building **v4-parity**: conformance vectors generated by executing the real Uniswap v4-core code
(commit 46c6834698c48bc4a463a86d8420f4eb1d7f3b75) on a local EVM, and harnesses that replay them against
off-chain re-implementations of v4 swap math (SDKs and aggregator pool simulators). The goal is to find
real, reproducible divergences (wrong quotes) in widely used implementations.

## Vectors
- Dev sample (small): `vectors/swaps.json`, `vectors/units.json`
- Full set (being generated, may appear later): `vectors/swaps.json`, `units.json`
- Generator source (read it to understand cases): `gen/generate.mjs`; oracle: `src/Oracle.sol`
- v4-core source for reference: `lib/v4-core/src/libraries/Pool.sol`, `SwapMath.sol`, `ProtocolFeeLibrary.sol`, `LPFeeLibrary.sol`

Swap vector shape:
```
{ id, pool: { tickSpacing, lpFee, protocolFeeZeroForOne, protocolFeeOneForZero, sqrtPriceX96, tick, liquidity,
              positions: [{tickLower, tickUpper, liquidity}] },
  swap: { zeroForOne, amountSpecified, sqrtPriceLimitX96, lpFeeOverride },
  expect: { amount0, amount1, amountToProtocol, swapFee, sqrtPriceX96, tick, liquidity } | { revert: "<selector>" } }
```
- `pool.tick`/`pool.liquidity` are the on-chain slot0 tick and in-range liquidity AFTER positions were added (what an indexer reads).
- Initialized ticks: for each position, liquidityNet[tickLower] += L, liquidityNet[tickUpper] -= L; liquidityGross += L on both.
- v4 sign convention: `amountSpecified < 0` = exact input, `> 0` = exact output (OPPOSITE of v3). `expect.amount0/1` are BalanceDelta from the swapper's view: negative = swapper pays the pool, positive = swapper receives.
- `swapFee` is the total fee in pips actually applied: if protocolFee for the direction is 0 it equals the LP fee, otherwise ProtocolFeeLibrary.calculateSwapFee (protocol fee charged ON TOP of the LP fee: `pf + lp - pf*lp/1e6`). v4 protocol fees have been LIVE on mainnet v4 pools since Uniswap governance proposal 100 (executed 27 Jul 2026) on Ethereum, Arbitrum, Base, BNB, Polygon, OP Mainnet. This is the most important case to check: does the target account for slot0.protocolFee at all, and in the v4 way (on top, not carved out of the LP fee as in v3)?
- `lpFeeOverride` non-zero (has 0x400000 flag) = a dynamic-fee hook override; LP fee becomes `override & ~0x400000`. If the target cannot express this, skip those vectors and count them as "unsupported", not as mismatches.
- Static LP fees in v4 can be any value 0..1,000,000 and tickSpacing any 1..32767. If a target rejects these, count as "unsupported" and note it (that itself is a finding only if real live pools use such values; say so with care).

Unit vector shape: `{ fn, args: [...strings/bools/numbers], expect: <value> | [values] | { revert } }` for
getSqrtPriceAtTick, getTickAtSqrtPrice, getAmount0Delta(a,b,L,roundUp), getAmount1Delta, getNextSqrtPriceFromInput(p,L,amt,zeroForOne),
getNextSqrtPriceFromOutput, computeSwapStep(cur,target,L,amountRemaining,feePips) -> [sqrtNext, amountIn, amountOut, feeAmount]
(v4 sign: amountRemaining<0 = exact in), calculateSwapFee(protocolFee16, lpFee) .

## What to deliver
Work ONLY inside your directory `harnesses/<target>/` (create it). Write:
1. A harness program (in the target's language) that loads a vectors file path given on the command line and reports per-vector PASS / MISMATCH / TARGET_ERROR (target threw where v4 succeeded or vice versa) / UNSUPPORTED, writing `report.json` with counts and every mismatch (id, field, expected, got).
   - For swap vectors, feed the target the pool exactly as an integrator would from on-chain data: sqrtPriceX96, tick, liquidity, fee, tickSpacing, initialized ticks. If the target has a field for protocol fee, set it from the vector. If it has none, run it the way production integrators do and record that it has none.
   - Compare amount0, amount1, final sqrtPriceX96, tick, liquidity (where the target exposes them).
   - Run each vector twice if useful: once "as integrators use it" and, if the target supports a protocol-fee input, with it.
2. `FINDINGS.md`: for each distinct divergence class: one-paragraph description, root cause with file:line in the target's source (pin the exact package/commit version), a minimal reproducing vector, the size of the error (e.g. output overquoted by X bps on a 30 bps pool with 5 bps protocol fee), and whether it is a target bug, a missing feature, or a harness/vector problem. Be adversarial with yourself: before claiming a target bug, reproduce it with a hand-built minimal case and re-read the v4-core code to make sure the vector is right. Also check whether the divergence matters in production (e.g. does the aggregator read protocolFee from chain elsewhere in its code? search the repo).
3. A short `README.md` with exact commands to reproduce.
